ScoreRent

A renter-side decision workspace that turns inconsistent rental screenshots into a structured shortlist, checks application fit with explainable rules, and compares costs, requirements, amenities and commute before the user applies.

The problem

Rental decisions are scattered across screenshots, calculations and browser tabs.

A promising rental can still be a poor practical choice once the deposit, application fee, missing documents and daily commute are considered. Renters often have to reconstruct those trade-offs manually before deciding whether an application is worth the time and cost.

ScoreRent brings the decision into one workflow. It structures listing information, checks how the requirements fit the renter’s circumstances, preserves serious options in a shortlist and makes competing rentals directly comparable.

Core product question

Given this renter’s circumstances and shortlisted options, which rental is realistically workable—and what needs attention before applying?

The workflow

From listing screenshot to a more informed application decision.

The product connects four steps that renters usually complete with separate tools.

01

Capture

Users can upload several screenshots from the same rental listing. The application extracts rent, deposit, fees, location, required documents, amenities, factual advantages and visible limitations into a structured draft.

02

Verify

Extracted fields include supporting evidence, confidence and warnings. Unclear values remain empty rather than being guessed, and the user reviews or corrects every detail before saving.

03

Check

An explainable rules engine evaluates affordability, supporting documents, guarantor or bursary evidence, upfront-cost pressure and market demand, then returns reasons and practical next steps.

04

Compare

Two to four shortlisted rentals can be compared across monthly and upfront costs, amenities, pros, potential downsides and estimated driving, walking or cycling time to one destination.

Key engineering distinction

AI reads the listing. Transparent rules explain the decision.

ScoreRent does not ask a generative model to decide whether the user should apply. Gemini is used to convert unstructured screenshots into reviewable structured facts; the application-fit result is produced separately by deterministic domain logic.

Screenshot text is treated as untrusted input. The extraction prompt prohibits following instructions embedded in an image, requires visible evidence, returns null for uncertain values and excludes private contact details. Pydantic validation then checks the structured response before the user sees it.

Why separate the systems?

Probabilistic extraction is useful for reading messy listings. A consequential recommendation is easier to test and challenge when its rules remain explicit.

Application-fit model

A result the renter can inspect instead of simply accepting.

The score supports the decision, but the explanation and next action carry the real value.

01

Affordability

Rent is assessed against qualifying income or support using calculated budget bands and progressive penalties when the ratio moves beyond the recommended range.

02

Application evidence

The engine checks standard documents for workers, new professionals and students, along with requirements entered from the individual listing.

03

Student circumstances

Bursary coverage, NSFAS or funding confirmation, guarantor income and guarantor documents are handled as distinct application paths rather than forcing every renter through one rule set.

04

Practical pressure

Deposit, first month’s rent and application fees are combined to expose upfront-cost pressure, while area demand provides context about likely competition.

05

Information confidence

Confidence reflects how complete the supplied rent, income, document and support information is. Missing inputs reduce certainty instead of being silently treated as favourable.

06

Actionable output

Every result includes a verdict, reasons, prioritised actions and a line-by-line score breakdown showing how each factor changed the result.

Shortlist and comparison

The best rental is not always the one with the lowest monthly price.

ScoreRent keeps financial, application and everyday-living trade-offs in the same decision view.

Complete cost picture

Monthly rent, deposit, application fees and calculated upfront cost are stored separately so a lower advertised rent does not hide a more difficult first-month commitment.

Structured listing trade-offs

Amenities, factual advantages, visible limitations, notes and source links are saved with each listing instead of being lost across screenshots and open tabs.

One destination, several routes

When an exact location is available, each selected listing is checked against the same workplace, campus or other destination for driving, walking and cycling distance and duration.

User-controlled location precision

Commute calculations are enabled only when the user confirms an exact address or sufficiently identifiable building, preventing suburb-level locations from being presented as precise routes.

Architecture

Small, explicit services around a testable decision core.

FastAPI and server-rendered interfaces

Routes cover public evaluation, authentication, renter profiles, saved results, listing imports, shortlist management and comparisons while Jinja2 keeps the deployed product lightweight.

Deterministic domain service

Currency normalisation, document aliases, scoring adjustments, confidence and verdict logic live outside the presentation layer and can be tested without browser requests.

Structured multimodal extraction

Image validation, resizing, rate limiting, schema-constrained Gemini responses and canonical document mapping sit behind a dedicated listing-import service.

PostgreSQL ownership and history

Profiles, evaluations and listings are scoped to authenticated users, with saved snapshots preserving the information that produced each result.

Geospatial service boundary

Address geocoding and route calculation are isolated from listing routes, with clear errors when a location is incomplete or an external service cannot provide a route.

Safe failure and user review

The application falls back to manual entry when screenshot extraction is unavailable and never treats AI-extracted data as final without a confirmation step.

What this project demonstrates

Software, AI and analytical thinking in one product.

ScoreRent demonstrates full-stack product development, multimodal AI integration, structured data extraction, explainable rule-based modelling, confidence-aware outputs, geospatial comparison, authentication, persistence and the design of a decision tool that supports users without claiming to predict a landlord’s approval.

Product boundary

Decision support, not an approval prediction.

ScoreRent helps users organise and evaluate the information they already have. It does not verify that a listing is legitimate, replace professional financial or legal advice, or guarantee that a landlord or agent will accept an application.
