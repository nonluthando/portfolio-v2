SA Tech Job Market Intelligence

A pipeline that collects public technology vacancies straight from employer career sites, standardises them, extracts skills and classifies each role. Deterministic rules come first, with machine learning and Gemini used only as separate, auditable suggestion layers.

The problem

Job boards repeat each other, and job descriptions describe seniority inconsistently.

Reading employers’ own career portals gives a cleaner view of the South African technology market, but each platform has its own API, pagination and location format. Titles and descriptions rarely say “graduate” or “senior” in the same way, so seniority, skills and workplace type have to be inferred carefully, and the inference has to be defensible.

  • Reproducible: raw responses are stored unchanged with timestamps and hashes, so any transformation can be re-run and audited.
  • Conservative deduplication: stable provider identifiers track first-seen and last-seen dates without merging unrelated vacancies.
  • Validated marts: jobs.parquet is the one-row-per-vacancy source of truth, and dashboard marts are checked against a contract before Streamlit and DuckDB read them.

Machine learning and AI

Three layers, each doing what it is best at.

Classification evidence is kept so every label can be explained. Where rules cannot decide, optional models suggest a value and write it to a separate, regenerable file instead of the canonical dataset.

Layer 1 · Rules

Scored, explainable classifier

Title-word precedence and numeric experience ranges decide career level, role, domain and employment type. When evidence conflicts, the label falls back to unspecified rather than guessing. A regex audit against the live dataset found and fixed six confirmed bugs.

Layer 2 · Machine learning

TF-IDF + logistic regression

A scikit-learn model learns from the rules’ own high-confidence labels, then suggests a role level for vacancies still unspecified, with a confidence score. Because the classes are heavily imbalanced, it is evaluated with macro-F1 rather than accuracy.

Layer 3 · LLM

Gemini-assisted suggestions

Gemini proposes role level, workplace type and city for target-market vacancies that are still missing one of them. Every field comes with a confidence and rationale, and only the fields that were actually unresolved are kept.

Why the layers are separate. The ML and Gemini outputs are manually run, gitignored artefacts with their own ml_ and llm_ field prefixes, so analysis can compare them with the rules instead of silently trusting them. A consistency test keeps the two rule-based classifiers from drifting apart.

What this project demonstrates

Data engineering, applied ML and responsible AI use in one pipeline.

It shows multi-source ingestion, immutable raw data, schema and quality validation, NLP-style skills extraction, a properly evaluated scikit-learn model, and LLM output treated as evidence to be checked, not as ground truth.
