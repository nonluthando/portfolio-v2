🔎 Retrieval-augmented generation in ProofLoop

I introduced RAG to improve the platform’s discoverability and learnability: new users can ask how a feature works and get a cited answer. The Help Assistant answers only from trusted project documentation, retrieves evidence first, and refuses when the evidence is not enough.

Markdown docsHeading-aware chunksGemini embeddingspgvectorSimilarity floor[Source N] answer
  • Grounded: embeddings and relational data share one PostgreSQL database, and chunks below a similarity threshold never reach the model.
  • Refuses safely: no evidence, an explicit NOT_SUPPORTED, or an answer with no valid citation all produce a refusal.
  • Measured: 21 retrieval evaluation cases, an opt-in faithfulness judge, and a query log with latency and citations.

🧭 Product thinking

Alongside the engineering, I work the way a product owner does: start from a real user problem, decide what is in and out of scope, make trade-offs explicit, and write the decisions down.

Problem framing

Start from a real cost to a real user

ScoreRent began with my own final-year rental search, where non-refundable application fees and missing documents made every rejected application expensive. The product exists to reduce wasted applications, aimed at students, graduates and first-time renters.

ScoreRent case study →

Evidence-led scope

Change the scope when the data says so

The job-market project found only 2 early-career technology roles in an early build, so I widened it to the whole South African tech market and kept early career as a lens. Low availability became a measurable finding, with sample-size warnings, instead of a failure.

Job-market case study →

Reducing cognitive load

Remove decisions, not options

ProofLoop was aimed at the decision fatigue of choosing what to study and when, using spaced review and a daily plan that recommends the next action. ScoreRent applies progressive disclosure to avoid cognitive overload: the verdict leads, and the detail opens when the renter wants it.

Product decisions →

Prioritisation

Say what you will not build

ProofLoop’s user-created roadmaps shipped with up/down controls instead of drag-and-drop, and with no sharing, templates or collaboration yet, because those added complexity without improving the core workflow. Application tracking is explicitly out of scope.
